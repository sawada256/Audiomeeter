# Design review and improvements (2026-10-18)

The whole code base (engine, DSP, device IO, VST3 worker/IPC, state, UI, and the HAL IO path) was read statically and the existing regression suite was run; issues that could be reproduced or clearly explained were fixed. Real-hardware HAL replacement and long-run device tests were not performed.

## Design summary

- The A1 device IOProc is the master clock. Other inputs/outputs absorb independent clocks through SPSC rings and an adaptive (PI-controlled) resampler.
- A 10-node graph (5 inputs + 5 buses) is processed in topological order; only cyclic sidechains read the previous block. PDC is recomputed every block from per-node latency.
- Each VST3 instance runs in its own process, with nonblocking shared-memory IPC and one block of latency. Late or crashed workers fall back to a latency-matched dry signal.

## Fixed in this change

| Area | Problem | Fix |
|---|---|---|
| Dropouts | Insert bypass (including left-clicking a bus slot) and INSERT chain ON/OFF stopped and restarted every device through `withStoppedAudio` | Bypass and chain disable are now atomic flags/masks; switching never stops audio |
| VST | After un-bypassing, the worker replayed the block it rendered before the bypass | Resume resynchronizes the IPC (`vmw_resync`), dropping the stale wet block and dry history. Regression test added (verified to fail without the fix) |
| VST | `getStateInformation` ran under the callback lock; with an editor open this stalled the audio thread every 2 s and could fault large-state plugins | State is read without the lock, as DAW hosts do |
| VST | The worker render thread used ordinary QoS and missed deadlines under load | Time-constraint (real-time) scheduling; the kernel demotes it if it overruns |
| VST | Relaunching workers for a rate/buffer change could lose the last 2 s of editor edits | A state snapshot is requested first (up to 0.5 s wait) |
| Real-time safety | Publishing the compensation dictionary caused a copy-on-write allocation every cycle | Fixed-size arrays with element copies |
| Real-time safety | Each UI change freed the previous settings snapshot (dictionaries, strings, EQ arrays) on the audio thread | The old snapshot is retired and released on a non-real-time thread |
| Real-time safety | Array-literal allocations in FORMANT coefficients and tap clearing | Allocation-free |
| Memory | Delay lines (~8.4 MB each) per bus/insert were fully written even at zero delay (most of the ~230 MB RSS) | calloc, zero-delay pass-through and logical reset: only lines with a real delay commit memory; large memsets on start are gone |
| Meters | Peak fall was per block, so ballistics changed up to 128× with buffer size | Time-based decay (keeps the 256-frame/48 kHz behavior); vDSP computation |
| DSP | A legacy `intellipan.x` on virtual strips could add a hidden second balance stage | Virtual strips use only PAN |
| UI | No Edit menu, so ⌘C/⌘V/⌘A did not work in the plugin search field | Standard Edit menu |

## New: MIDI controller mapping

See [User guide › MIDI controllers](USAGE.en.md). All CoreMIDI inputs are received; CC, notes and pitch bend can control strips, buses and the recorder. MIDI Learn, two relative encoder formats, pickup (soft takeover) and toggle/follow buttons are supported. Incoming messages are batched into one UI update and use the same setters as the mouse.

## Addressed in round 2

| # | Item | Change |
|---|---|---|
| 1 | Insert add/remove/reorder/sidechain, EQ position and latency toggles stopped all devices | Insert chains are RCU snapshots; options and stage order are atomics. Changes apply without stopping audio; retired snapshots are released on the UI thread after the callback moved on |
| 2 | IO on the A1 device used extra IOProcs and rings | Served directly in the master IOProc (no ring, priming or clock correction); other channels of the same device are added to the A1 output buffer |
| 3 | Bypass changed latency | Soft (latency kept, gray) and full (removed, black) bypass; the default is configurable and Option-click uses the other kind |
| 4 | No recovery after quarantine | Crashed or late workers are replaced 2 s later with the same settings and state, without stopping audio (up to 3 per minute, can be disabled) |
| 5 | EQ coefficients stepped | Coefficients ramp over one block; disabled bands glide to unity before being skipped |
| 6 | Stepped lookahead-limiter attack | Moving average over the lookahead window gives a linear attack while still bounding the peak |
| 7 | Silent recording overruns; whole-file playback with linear interpolation | Dropped recording frames are shown in the UI and diagnostics. Playback streams from a reader thread through AVAudioConverter (band-limited SRC) with exact segment switching on seek |
| 9 | Graph rebuilds allocated on the audio thread | In-place recomputation on preallocated arrays |
| 10 | VST3 MIDI input and soft bypass | Lock-free MIDI from the CoreMIDI thread to workers (off / all / one channel); the VST3 bypass parameter is used, or latency-matched dry audio |

Item 8 (HAL trim lookup) remains. A ThreadSanitizer run confirmed no races while chains, bypass states and options change during rendering.

## Added in round 2

- **Macro buttons**: Voicemeeter-like scripts (`Strip[i]`, `Bus[i]`, `Scene`, `Recorder`, `Button[i].State` with `=`/`+=`/`-=`/`toggle`), push/toggle/momentary, radio groups, keys and MIDI.
- **Scenes** (savable macros): routing, levels, Mute/Solo, EQ, dynamics and insert states, recalled with a selectable scope from buttons, macros or MIDI; JSON export/import.
- **MIDI Learn for VST3 parameters**: from the parameter list, or the parameter last moved in the plugin editor.
- **Routing matrix** and a **configurable layout** (3–5 hardware inputs, A1–A3 up to A1–A5).
- **Diagnostics**: load and overruns, per-path mode, ring state, ppm and latency, per-plugin processing time, late blocks and restarts, recording drops and playback underruns.

## Voicemeeter features not yet implemented (as of round 1; macro buttons and configuration saving were added in round 2)

VBAN network audio and remote control; Macro Buttons; MIDI mapping feedback to LEDs/motor faders; saving/loading named configurations; per-strip Send FX with FX returns (Potato); Patch Composite and 8-channel buses; 8-band/graphic bus EQ; ducking; a Remote API for external apps and Stream Deck.

## Proposals toward DAW-like flexibility (by priority)

1. Scenes/snapshots of routing, gains, EQ and insert state, recalled by click/MIDI/hotkey with a short crossfade.
2. MIDI feedback and controller profiles (X-Touch Mini, nanoKONTROL, Mackie Control) with banks.
3. MIDI Learn for VST3 parameters via a parameter-list/set IPC in the worker.
4. Host tempo and transport (BPM + AudioPlayHead) for tempo-synced plugins.
5. Aux send/return buses (DAW-style FX channels).
6. Simple automation: record and replay fader moves during recording.
7. A routing matrix view and a configurable number of strips.
8. A diagnostics view: CPU, IPC deadline misses, dropouts and actual path latency.
9. OSC/WebSocket API for phones, Stream Deck and TouchOSC.
