# 設計レビューと改善（2026-10-18）

コード全体（エンジン、DSP、デバイスIO、VST3ワーカー／IPC、状態管理、UI、HALのIO経路）を静的に読み、既存の回帰テストを実行したうえで、確実に再現・説明できる問題を修正しました。実機HALの入れ替え・長時間実機試験は行っていません。

## 設計の要点（確認結果）

- A1デバイスのIOProcがマスタークロック。他の入出力はSPSCリング＋適応型リサンプラ（PI制御）で独立クロックを吸収する構成で、方向性は妥当。
- 10ノード（入力5＋バス5）のグラフをトポロジカル順に処理し、循環するサイドチェインだけ1ブロック前の信号を使う。PDCはノードごとの遅延から毎ブロック計算。
- VST3は1インスタンス1プロセス。共有メモリ＋セマフォで1ブロック遅延のノンブロッキングIPC。遅延・クラッシュ時は遅延を保ったドライ信号に切り替わる。

## 今回修正した問題

| 区分 | 問題 | 修正 |
|---|---|---|
| 操作で音切れ | インサートのバイパス（バス上のスロット左クリックを含む）とINSERTチェーンのON/OFFが毎回 `withStoppedAudio` で全デバイスを停止・再起動していた | バイパスとチェーン無効化をアトミックなフラグ／マスクに変更し、音声を止めずに切替 |
| VST | バイパス解除直後、ワーカーがバイパス前に処理した古いブロックを再生していた（クリック・残響の断片） | 再開時にIPCを再同期（`vmw_resync`）し、古いwetブロックとドライ履歴を捨てる。回帰テスト追加（修正なしで失敗することを確認） |
| VST | 状態取得 `getStateInformation` をコールバックロック内で実行。エディタ表示中は2秒ごとに音声スレッドを止め、大きな状態のプラグインで遅延・フォールト（自動隔離）を起こし得た | DAWと同様にロックなしで取得 |
| VST | ワーカーの処理スレッドが通常のQoSで、高負荷時にブロック締め切りを落としやすい | 時間制約（リアルタイム）スケジューリングを設定。予算超過時はカーネルが降格 |
| VST | サンプルレート／バッファ変更でワーカーを再起動する際、直近2秒以内のエディタ操作が失われ得た | 再起動前に状態スナップショットを要求して最大0.5秒待機 |
| リアルタイム安全性 | 補正値辞書の公開で毎サイクル copy-on-write によるヒープ確保が発生 | 固定長配列＋要素コピーに変更 |
| リアルタイム安全性 | UI操作のたびに古い設定スナップショット（辞書・文字列・EQ配列）が音声スレッドで解放されていた | 旧スナップショットを退避し、UI側スレッドで解放 |
| リアルタイム安全性 | FORMANT係数更新時・タップ初期化時の配列リテラル確保 | 確保なしに変更 |
| メモリ | 遅延線（各約8.4 MB）がバス・インサートごとに常駐し、遅延0でも全ページを書き込んでいた（稼働中のRSS約230 MBの大半） | calloc＋遅延0時は素通し・論理リセットにして、実際に遅延を使う線だけメモリを消費。起動・再起動時の大規模memsetも解消 |
| メーター | ピーク減衰がブロック単位で、バッファサイズにより落ち方が最大128倍変わっていた | 時間基準に変更（256 frames/48 kHz時の挙動を維持）。vDSPで計算 |
| DSP | 仮想ストリップで旧設定の `intellipan.x` がPANと二重にバランスとして掛かり得た（UIから戻せない） | 仮想ストリップはPAN値のみ使用 |
| UI | Editメニューがなく、プラグイン検索欄で⌘C/⌘V/⌘Aが効かなかった | 標準のEditメニューを追加 |

## 新機能: MIDIコントローラー割り当て

使い方は[使い方 › MIDIコントローラー](USAGE.ja.md)。CoreMIDIの全入力を受け、CC／ノート／ピッチベンドを入力・バス・レコーダーの操作に割り当てます。MIDI Learn、相対エンコーダー2方式、ピックアップ（ソフトテイクオーバー）、ボタンのトグル／追従に対応。受信はバッチ化して1回のUI更新にまとめ、すべてマウスと同じ設定関数を経由します。

## 第2弾で対応した項目

| # | 項目 | 対応 |
|---|---|---|
| 1 | インサート追加・削除・並べ替え・サイドチェイン、EQ位置、遅延補正トグルで全停止 | インサートチェーンをRCU（不変スナップショットの差し替え）にし、オプションと信号順序をアトミック化。音声を止めずに反映。旧スナップショットは音声スレッドが離れた後にUIスレッドで解放 |
| 2 | A1と同じ機器の入出力が別IOProc＋リング経由 | マスターIOProc内で直接読み書き（リング・起動待ち・クロック補正なし）。同じ機器の別チャンネル出力はA1の出力バッファへ追記 |
| 3 | バイパスで遅延が変わる | 簡易（遅延維持／グレー）と完全（経路から除外／黒）の2種類。既定を設定で選び、⌥クリックでもう一方 |
| 4 | 隔離後に自動復帰しない | クラッシュ・処理落ちから2秒後に、同じ設定と状態で新しいワーカーへ無停止で差し替え（1分に3回まで、設定でOFF可） |
| 5 | EQ係数の瞬時切替 | 係数を1ブロックかけて補間。無効化したバンドは単位応答まで滑らかに移行してから省略 |
| 6 | 先読みリミッターのアタックが段差 | 先読み窓の移動平均でゲインを直線的に下げる方式に変更（ピーク時刻の上限は保証） |
| 7 | 録音リング溢れが無通知、再生は全量展開・線形補間 | 録音の欠落フレームを画面と診断に表示。再生は読込スレッドからのストリーミング＋AVAudioConverter（帯域制限SRC）、シークは区間単位で正確に切替 |
| 9 | サイドチェイングラフ再構築で確保 | 事前確保した配列をその場で再計算（音声スレッドで確保なし） |
| 10 | VST3: MIDI入力・ソフトバイパス | CoreMIDIスレッドからワーカーへロックフリーでMIDIを送信（OFF／全ch／ch指定）。VST3のbypassパラメーターを使用（無い場合は遅延を合わせた原音） |

8（HALのtrim探索）は今回対象外。ThreadSanitizer下で、音声処理中のチェーン差し替え・バイパス・オプション変更の連続実行に競合がないことを確認しました。

## 追加機能（第2弾）

- **マクロボタン**: Voicemeeter風スクリプト（`Strip[i]`, `Bus[i]`, `Scene`, `Recorder`, `Button[i].State`、`=`/`+=`/`-=`/`toggle`）、押す／トグル／押している間、ラジオグループ、キー・MIDI割り当て。
- **シーン**（保存できるマクロ）: ルーティング・音量・Mute/Solo・EQ・ダイナミクス・INSERT状態を一括保存し、範囲を選んで呼出。ボタン・マクロ・MIDIから呼出、JSONで書き出し／読み込み。
- **VST3パラメーターのMIDI Learn**: パラメーター一覧から選択、またはプラグイン画面で最後に動かしたパラメーターを割り当て。
- **ルーティングマトリクス**と**入出力数の可変化**（ハードウェア入力3〜5、物理バスA1–A3〜A5）。
- **診断画面**: 処理負荷・締切超過、各経路の方式・リング状態・ppm・遅延、プラグインの処理時間・遅延ブロック・再起動回数、録音欠落・再生途切れ。

## 本家Voicemeeterにあり、未実装の便利機能（第1弾時点。マクロボタン・構成保存は第2弾で対応）

- **VBAN**（ネットワーク音声送受信）とVBAN-Text／リモート操作。
- **Macro Buttons**（ボタンにスクリプト・ルーティング一括切替を割り当て）。今回のMIDIと組み合わせると効果が大きい。
- **MIDI Mapping のフィードバック**（LED・モーターフェーダーへの状態送信）。今回の受信部の上に追加可能。
- **パッチ／複数構成の保存・読込**（XML設定の保存、起動時ロード）。
- **入力ストリップのSend FX（リバーブ／ディレイ）と Fx Return**（Potato）。
- **Patch Composite、マルチチャンネル（8ch）バス**、**バスのEQ 8バンド＋グラフィックEQ**。
- **Ducking／Sidechainによる自動音量制御**（通話時にBGMを下げる）。
- **リモートAPI**（Voicemeeter Remote API相当: 外部アプリ・Stream Deckからの操作）。

## DAW的な自由度に向けた提案（優先順）

1. **シーン／スナップショット**: ルーティング・ゲイン・EQ・インサート状態を名前付きで保存し、ワンクリック／MIDI／ホットキーで呼び出し（短いクロスフェード付き）。
2. **MIDIフィードバックとコントローラープロファイル**: X-Touch Mini、nanoKONTROL、Mackie Controlなどのテンプレート。バンク切替。
3. **VST3パラメーターのMIDI Learn**: ワーカーにパラメーター一覧・設定のIPCを追加し、任意プラグインのつまみを割り当て。
4. **ホスト側テンポとトランスポート**（BPM設定＋AudioPlayHead）で、テンポ同期型ディレイ等を正しく動かす。
5. **Aux Send / Return バス**: 入力ごとのセンド量で共有エフェクトに送る（DAWのFXチャンネル）。
6. **オートメーション（簡易）**: レコーダー録音中のフェーダー操作を記録・再生。
7. **ルーティングマトリクス表示**（入力×出力のグリッド、ドラッグで接続）とストリップ数の可変化。
8. **診断ビュー**: CPU負荷、IPC遅延超過回数、ドロップ数、各経路の実遅延をリアルタイム表示。
9. **OSC／WebSocket API**: スマートフォン・Stream Deck・TouchOSCからの遠隔操作。
