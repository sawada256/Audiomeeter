# 設計レビューと改善（2026-10-18）

コード全体（エンジン、DSP、デバイスIO、VST3ワーカー／IPC、状態管理、UI、HALのIO経路）を静的に読み、既存の回帰テストを実行したうえで、確実に再現・説明できる問題を修正しました。実機HALの入れ替え・長時間実機試験は行っていません。

## 設計の要点（確認結果）

- A1デバイスのIOProcがマスタークロック。他の入出力はSPSCリング＋適応型リサンプラ（PI制御）で独立クロックを吸収する構成で、方向性は妥当。
- 10ノード（入力5＋バス5）のグラフをトポロジカル順に処理し、循環するサイドチェインだけ1ブロック前の信号を使う。PDCはノードごとの遅延から毎ブロック計算。
- VST3は1インスタンス1プロセス。共有メモリ＋セマフォで1ブロック遅延のノンブロッキングIPC。遅延・クラッシュ時は遅延を保ったドライ信号に切り替わる。

## 今回修正した問題

| 区分 | 問題 | 修正 |
|---|---|---|
| 操作で音切れ | インサートのバイパス（バス上のスロット左クリックを含む）とINSERTチェーンのON/OFFが毎回 `withStoppedAudio` で全デバイスを停止・再起動していた | バイパスとチェーン無効化をアトミックなフラグ／マスクに変更し、音声を止めずに切替 |
| VST | バイパス解除直後、ワーカーがバイパス前に処理した古いブロックを再生していた（クリック・残響の断片） | 再開時にIPCを再同期（`vmw_resync`）し、古いwetブロックとドライ履歴を捨てる。回帰テスト追加（修正なしで失敗することを確認） |
| VST | 状態取得 `getStateInformation` をコールバックロック内で実行。エディタ表示中は2秒ごとに音声スレッドを止め、大きな状態のプラグインで遅延・フォールト（自動隔離）を起こし得た | DAWと同様にロックなしで取得 |
| VST | ワーカーの処理スレッドが通常のQoSで、高負荷時にブロック締め切りを落としやすい | 時間制約（リアルタイム）スケジューリングを設定。予算超過時はカーネルが降格 |

| リアルタイム安全性 | 補正値辞書の公開で毎サイクル copy-on-write によるヒープ確保が発生 | 固定長配列＋要素コピーに変更 |
| リアルタイム安全性 | UI操作のたびに古い設定スナップショット（辞書・文字列・EQ配列）が音声スレッドで解放されていた | 旧スナップショットを退避し、UI側スレッドで解放 |

| DSP | 仮想ストリップで旧設定の `intellipan.x` がPANと二重にバランスとして掛かり得た（UIから戻せない） | 仮想ストリップはPAN値のみ使用 |
| UI | Editメニューがなく、プラグイン検索欄で⌘C/⌘V/⌘Aが効かなかった | 標準のEditメニューを追加 |

## 新機能: MIDIコントローラー割り当て

使い方は[使い方 › MIDIコントローラー](USAGE.ja.md)。CoreMIDIの全入力を受け、CC／ノート／ピッチベンドを入力・バス・レコーダーの操作に割り当てます。MIDI Learn、相対エンコーダー2方式、ピックアップ（ソフトテイクオーバー）、ボタンのトグル／追従に対応。受信はバッチ化して1回のUI更新にまとめ、すべてマウスと同じ設定関数を経由します。

## 見つけたが今回は修正していない問題

1. **インサートの追加・削除・並べ替え・サイドチェイン変更、バスEQ位置、遅延補正トグル**は依然として全デバイス停止を伴う。ロックフリーなチェーン差し替え（RCU方式）で無停止化が可能。
2. **同一デバイスの二重クロック処理**: A1と同じ機器の入力・別チャンネル出力も、別IOProc＋リング＋リサンプラ経由（約3ブロックの余分な遅延と補間）。同一デバイスはマスターIOProc内で直接読み書きできる。
3. **バイパスで遅延が変わる**: バイパスするとプラグイン遅延がPDCから外れ、他経路の補正量が変わって一瞬音が飛ぶ。DAW同様「遅延を保ったバイパス」をオプション化するとよい。
4. **自動隔離後の復帰がない**: 250 ms連続で処理が間に合わないとワーカーを強制終了し、手動の「再読込」まで戻らない。スリープ復帰直後などに誤爆し得る。数回までの自動再起動を推奨。
5. **EQ係数の瞬時切替**: バスEQ・ストリップEQのドラッグ時に係数が飛ぶためジッパーノイズが出得る。係数補間またはクロスフェードが望ましい。
6. **先読みリミッターのアタックがステップ状**: 先読み区間内でゲインを直線的に下げると歪みが減る。
7. **録音リングの溢れが無通知**、再生ファイルを全量メモリ展開・線形補間（既知課題）。
8. **HALのクライアント別trim**は毎IOサイクル最大2048要素を線形探索。クライアントIDのハッシュ化で軽量化可能。
9. **サイドチェイン用グラフの再構築**は変化時のみだが音声スレッドで配列を確保する。
10. **VST3の未対応点**: AudioPlayHead（テンポ・再生位置）なし、MIDI入力なし、パラメーターのオートメーション／外部操作なし、ソフトバイパス（VST3 bypassパラメーター）未使用。

- **リモートAPI**（Voicemeeter Remote API相当: 外部アプリ・Stream Deckからの操作）。

## DAW的な自由度に向けた提案（優先順）

1. **シーン／スナップショット**: ルーティング・ゲイン・EQ・インサート状態を名前付きで保存し、ワンクリック／MIDI／ホットキーで呼び出し（短いクロスフェード付き）。
2. **MIDIフィードバックとコントローラープロファイル**: X-Touch Mini、nanoKONTROL、Mackie Controlなどのテンプレート。バンク切替。
3. **VST3パラメーターのMIDI Learn**: ワーカーにパラメーター一覧・設定のIPCを追加し、任意プラグインのつまみを割り当て。
4. **ホスト側テンポとトランスポート**（BPM設定＋AudioPlayHead）で、テンポ同期型ディレイ等を正しく動かす。
5. **Aux Send / Return バス**: 入力ごとのセンド量で共有エフェクトに送る（DAWのFXチャンネル）。
6. **オートメーション（簡易）**: レコーダー録音中のフェーダー操作を記録・再生。
7. **ルーティングマトリクス表示**（入力×出力のグリッド、ドラッグで接続）とストリップ数の可変化。
8. **診断ビュー**: CPU負荷、IPC遅延超過回数、ドロップ数、各経路の実遅延をリアルタイム表示。
9. **OSC／WebSocket API**: スマートフォン・Stream Deck・TouchOSCからの遠隔操作。
